# Recipe Saver

Instagramなどの投稿URL・画像・メモを保存する個人用アプリです。
今回の変更はローカルのみです。GitHub、Firebase、Cloudinaryの本番設定・データは変更していません。

## ローカル確認

## 修正内容（重要度順）

### High

- 保存内容はDOMの `textContent` と属性プロパティで表示。HTML文字列の埋め込み・インラインイベント処理を廃止。
- 投稿URLはHTTP/HTTPSのみ。認証情報入りURLとスクリプトURLを拒否。画像はCloudinaryのHTTPS URLまたは同一オリジンのみ。
- Google認証と本人UIDによるアプリ側のアクセス判定を追加。未ログイン・別UIDでは取得・保存しない。
- 画像アップロード前に更新対象IDと入力を固定。保存中の閉じる・別投稿への移動・二重保存を防止。
- 認証が失われた場合、古い読み取り結果を表示せず、アップロード後のDB書き込みも開始しない。

### Medium

- 保存処理と投稿ごとのお気に入り・削除処理に実行中ガードを追加。失敗時は表示・入力を維持。
- 検索とカテゴリ変更は取得済みデータで処理し、操作ごとの全件問い合わせを廃止。
- 再取得時は最新のリクエスト結果だけを反映。保存後はローカルキャッシュを更新。
- 旧カテゴリを表示・検索・編集で統一して扱う。
- 画像読込失敗はモジュール内の `error` イベントで代替表示。
- 投稿を開く操作はリンク、編集・画像選択はボタン。ラベルを関連付け、編集画面は標準の `dialog` を使用。
- 読込失敗を未登録と区別し、再試行を表示。
- 旧 `index_v28.html` は最新版への移動ページへ変更。旧版から認証を迂回してDBへ接続するコードを残さない。

### Low

- 一時画像URLを差し替え・取消・編集終了時に解放。
- 検索0件では「条件に一致する投稿がありません」と条件解除ボタンを表示。
- カードDOMを再利用し、変更のない検索結果では再構築しない。画像は遅延読み込み。
- HTML、CSS、画面表示、状態管理、通信処理、共通データ変換を分離。

## 公開前に必要な設定と現在の状態

本人専用の構成です。既存投稿に所有者フィールドを追加する移行は不要です。
ただし、**アプリのログイン画面だけでは既存の公開データを保護できません。Firestore側のルール適用が必須です。**

ユーザー提供のUIDをアプリ設定・ルール案に反映済みです。提供された既存ルールを保存し、統合版 `security/firestore.rules` をローカルに作成しました。既存のユーザー別10ブロックの完全一致、Instagramの全許可の除去、UIDの一致を静的に照合済みです。Firebase管理画面の現在値を取得したものではないため、適用前には提供後の変更がないことも確認します。

1. Firebase AuthenticationでGoogleログインが有効で、ご本人のGoogleアカウントに対応するUIDであることを確認します。Google認証のユーザーが未登録の場合は、初回の実Googleログインが必要です。模擬ログインではFirebaseユーザーは作成されません。
2. Authenticationの承認済みドメインに、公開先の `orangemark0808-code.github.io` を登録します。
3. `src/config.mjs` の `ownerUid` と `security/firestore.rules` の許可UIDは同じ値に設定済みです。本人以外のアカウントを許可する変更はしません。
4. **現在のFirestoreルールと提供済みの控えを比較してから**、統合版 `security/firestore.rules` をルールエディタに入れて検証します。統合版にはPROMPT-STOCK、ミタモノ、ユーザー共通メタデータ、ネタキロク、イロイロキロク、Blog Editorの既存ルールが含まれています。部分サンプル `security/firestore.rules.example` でルール全体を置き換えないでください。
5. 提供ルールではInstagramのブロックだけに `allow read, write: if true` があり、統合版では置換済みです。全体に一致する別の許可は提供ルールにはありません。Firestoreは一致する `allow` のいずれかが許可するとアクセスできるため、適用時に後から追加された全体許可などがないか確認します。
6. FirebaseのルールシミュレーターまたはEmulatorで、未認証・別UIDの読取/作成/更新/削除が拒否され、本人の操作と既存投稿の編集が許可されることを確認します。ルール案のEmulator実行・本番適用はまだ行っていません。
7. ユーザーの確認後に、ルール適用・GitHub反映を調整します。ルールを厳しくすると、旧公開画面からの未認証アクセスは拒否されます。

ルールプレイグラウンドの手順とテストデータは `security/VALIDATION.md` を参照してください。ルール公開・GitHub反映は引き続き保留です。

Cloudinaryは既存のunsigned upload presetを利用しています。今回のルールはFirestoreの一覧・メモを保護しますが、**既存の公開画像URLの非公開化や、アップロードAPIへの直接アクセス制限は行いません**。画像も本人以外からアクセスできないようにする場合は、認証付きストレージへの変更が別途必要です。Cloudinaryの容量・形式・利用制限は管理画面側でも設定してください。
